# Wind Forecast Agent — прогноз мощности ветротурбин

Проект строит почасовой прогноз **нормализованной активной мощности двух ветротурбин на 48 часов**. Он помогает оценить ожидаемую выработку по прогнозу погоды, когда фактическая мощность будущих часов ещё неизвестна. Текущая версия подготовлена для ретроспективного прогноза на февраль 2026 года и позволяет изучать результаты через веб-интерфейс или командную строку.

Мощность представлена числом от `0` до `1` относительно шкалы в исходных данных; это не кВт и не оценка суммарной выработки всей ВЭС.

## Что реализовано

- Прогноз для турбин **1 и 2**: 48 последовательных часовых значений для выбранного выпуска.
- Подготовка 10-минутных измерений SCADA, подбор доступных на момент выпуска погодных прогнозов и построение погодных и календарных признаков.
- Обучение и сравнение эмпирической кривой мощности, модели поправки к ней (`residual`) и прямой модели (`direct`). В сохранённых артефактах для обеих турбин выбран вариант `direct` на LightGBM.
- `ForecastAgent`: загрузка данных, запуск модели, проверка полноты погоды и диапазона прогноза, сохранение каждого успешного запуска в отдельный JSON с версией модели и происхождением погоды.
- Интерфейс Streamlit: выбор турбины и одной даты либо всего февраля; график, таблица, тепловая карта месяца, журнал шагов агента, выгрузка месячного прогноза в CSV. Интерфейс показывает метрики исторической валидации из сохранённых манифестов.
- CLI для отдельного выпуска и `predict.py` для пакетного воспроизведения ежедневных февральских выпусков в CSV.

## Как работает решение

1. Пользователь выбирает турбину и дату. Для 1 февраля 2026 года выпуск происходит **31 января в 17:00 UTC**, то есть в 23:00 по фиксированным часам SCADA `UTC+6`.
2. Агент читает погодный архив Open-Meteo Previous Runs из `data/cache/` и для каждого целевого часа выбирает последний прогнозный запуск, который мог быть доступен к моменту выпуска. Если подходящих данных нет, полный прогноз не сохраняется.
3. `src/ml_bridge.py` загружает историю SCADA и обученные артефакты. `src/features.py` формирует признаки из прогнозного ветра, температуры и времени; `src/model.py` рассчитывает 48 значений мощности. Лаги фактической SCADA не входят в признаки итоговой модели.
4. `ForecastAgent` проверяет 48 последовательных часов и значения мощности в диапазоне `0–1`, записывает версионированный JSON в `forecasts/`, а интерфейс отображает результат. Первый час выпуска от 31 января соответствует 1 февраля, 00:00 по часам SCADA.

## Технологии

| Технология | Роль |
| --- | --- |
| Python 3.10+ | Основной код и CLI |
| pandas, NumPy | Временные ряды, подготовка данных и расчёты |
| LightGBM | Обученная модель прогноза мощности |
| joblib | Сохранение и загрузка артефактов модели |
| Streamlit, Plotly | Веб-интерфейс и графики |
| requests | Загрузка данных Open-Meteo при отсутствии кэша |
| scikit-learn | Отдельный экспериментальный baseline в `src/forecast_pipeline.py` |

Генеративная модель или LLM API в прогнозном контуре не используется: `ForecastAgent` — Python-оркестратор погодных данных и обученной ML-модели. Список зависимостей находится в [requirements.txt](requirements.txt).

## Архитектура проекта

| Компонент | Назначение |
| --- | --- |
| `app.py`, `src/agent_cli.py` | Ввод параметров и представление результата |
| `src/forecast_agent.py` | Последовательность вызовов, проверки и сохранение JSON |
| `src/ml_bridge.py` | Связь агента с погодным архивом, SCADA и моделью |
| `src/weather.py`, `src/data.py` | Выбор исторически доступной погоды и агрегация измерений турбин |
| `src/features.py`, `src/physics.py`, `src/model.py` | Признаки, эмпирическая кривая мощности и ML-инференс |
| `train.py`, `predict.py` | Обучение с валидацией и пакетный replay февраля |
| `data/raw/`, `data/cache/`, `artifacts/`, `forecasts/` | Исходные данные, погодный кэш, обученные модели и результаты |

Основной путь: **Streamlit или CLI → ForecastAgent → погодный кэш + SCADA + артефакты модели → проверенный прогноз → JSON**. `predict.py` использует то же ML-ядро для пакетного создания CSV без интерфейса агента.

Подробнее об обучении и контракте агента: [ML-ядро](docs/ml.md) и [ForecastAgent](docs/FORECAST_AGENT.md).

## Установка и запуск

Нужен Python **3.10 или новее** (минимум по синтаксису исходного кода). Команды выполняются из корня репозитория. Исходные CSV, кэш Open-Meteo и обученные артефакты включены в Git: для демонстрации не требуется повторное обучение или ключ API.

### Windows PowerShell

```powershell
git clone https://github.com/BAITC-Hacks/hack-8ffdfbfa-zhetysutech.git
cd hack-8ffdfbfa-zhetysutech
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m streamlit run app.py
```

Если репозиторий уже получен, первые две команды не нужны. Адрес локальной страницы выведет Streamlit при запуске.

### Linux / macOS

```bash
git clone https://github.com/BAITC-Hacks/hack-8ffdfbfa-zhetysutech.git
cd hack-8ffdfbfa-zhetysutech
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python -m streamlit run app.py
```

Погодный кэш используется без сети. Если нужного кэша нет, `src/weather.py` запрашивает Open-Meteo Previous Runs API; для этого потребуется доступ к сети.

## Как проверить решение

1. Запустите Streamlit по инструкции выше.
2. Выберите **«Турбина 1» → «Одна дата» → 01.02.2026 → RUN**.
3. Проверьте график и таблицу с **48** почасовыми значениями прогноза, скоростью ветра и номером часа горизонта. Журнал показывает шаги агента и путь к сохранённому JSON в `forecasts/streamlit/`.
4. Для просмотра всех выпусков выберите **«Весь февраль»**: интерфейс построит тепловую карту и позволит скачать CSV. Это 28 отдельных выпусков по 48 часов для выбранной турбины.

Тот же отдельный выпуск можно проверить без интерфейса:

```powershell
.\.venv\Scripts\python.exe -m src.agent_cli --turbine 1 --issue-time '2026-01-31T17:00:00Z'
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

CLI печатает JSON с `rows: 48` и путём к файлу прогноза в `forecasts/`. Входное время должно содержать часовой пояс. Дополнительная проверка совпадения агента с сохранённым пакетным replay в PowerShell:

```powershell
.\.venv\Scripts\python.exe scripts/check_agent_replay.py
```

Сохранённые манифесты фиксируют средний MAE на трёх исторических фолдах **ноябрь 2025 — январь 2026** для выбранного варианта `direct`:

| Турбина | Средний MAE, нормализованная мощность |
| --- | ---: |
| 1 | 0,1785 |
| 2 | 0,1760 |

Это оценки исторической валидации из `artifacts/manifest_t1.json` и `artifacts/manifest_t2.json`, **не оценка февраля 2026 года**.

## Данные и интеграции

- `data/raw/turbine1.csv` и `data/raw/turbine2.csv` содержат 10-минутные измерения SCADA: скорость ветра, нормализованную активную мощность и температуру. `src/data.py` усредняет их по часам; часы с менее чем четырьмя измерениями из шести не используются как фактические метки.
- Погодный источник — [Open-Meteo Previous Runs API](https://previous-runs-api.open-meteo.com/v1/forecast): прогноз скорости ветра на 100 м и температуры на 2 м из предыдущих запусков. Кэш CSV и метаданные источника находятся в `data/cache/`.
- `artifacts/model_t*.joblib`, `artifacts/booster_t*.txt`, `artifacts/manifest_t*.json` содержат сохранённые модели и сведения о валидации. Готовые CSV пакетного replay находятся в `forecasts/`; новые запуски агента сохраняются там же в JSON.
- Внешний сервис во время работы нужен только при повторной загрузке отсутствующего погодного кэша. Ключ API в текущей реализации не используется.

## Ограничения текущей версии

- Настроены только две турбины и фиксированный горизонт 48 часов. Интерфейс ограничивает выбор дат февралем 2026 года; исторический кэш также имеет конечный период.
- В исходных данных нет фактической мощности за февраль 2026 года, поэтому MAE/RMSE на этом периоде вычислить нельзя. Показанные в интерфейсе метрики относятся к историческим фолдам.
- Мощность нормализована; номинальная мощность и паспортные кривые турбин в проекте отсутствуют. Перевод прогноза в кВт не реализован.
- Правило доступности погодных запусков использует задержку публикации **12 часов**. Для исторических запусков это допущение, а не подтверждённое время публикации каждого выпуска.
- Агент запускается по запросу UI или CLI; фонового расписания обновления прогнозов нет.
- Отдельный ранний baseline `src/forecast_pipeline.py` ожидает имена файлов `turbine_1.csv` и `turbine_2.csv`, которых в `data/raw/` нет. Для воспроизводимой проверки используйте Streamlit или `src.agent_cli`.
